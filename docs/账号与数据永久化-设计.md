# 游伴 YouBan · 账号与数据永久化设计

> 状态日期：**2026-09-30**。第 1–5 节是**已上线并验证**的实现；第 6 节起是规划。
> 总览见 [技术总览与开发路径](技术总览与开发路径.md)。

## 1. 要解决的问题

内测反馈：每次新开网页数据都没了，换设备更不用说，起不到测试效果。目标：

1. 有账号。登录后**进度与攻略簿跟人走**，手机、网页、桌面客户端互通。
2. 不登录也能用（游客），数据存本机；之后登录**自动带上**，不丢。
3. 日后接手机号 / 微信时，**业务数据不迁移**。

## 2. 身份模型

```
                      ┌─────────────── auth.users（Supabase Auth）───────────────┐
  内测账号（账号名+密码）│  id (uuid) ◄── 所有业务表的 user_id 都指向它              │
  手机号（规划）      ──►│  一个人 = 一行；登录方式是挂在这一行上的「钥匙」            │
  微信（规划）        ──►│                                                          │
                      └──────────────────────────────────────────────────────────┘
  游客：没有 user_id，只有设备号 device_id（客户端首次启动生成的 uuid，存本机）
```

| 身份 | 凭据 | 进度存哪 | 攻略簿存哪 |
|---|---|---|---|
| 游客 | 请求头 `x-yb-device` | 只在本机 `localStorage` | 云端，按 `device_id` |
| 登录用户 | `Authorization: Bearer <access_token>` | 云端 `user_game_progress` + 本机缓存 | 云端，按 `user_id` |

**内测账号的实现细节**：Supabase Auth 需要邮箱或手机号作主键，所以账号名 `biao` 在内部存为 `biao@u.youban.app`。这个邮箱不收信、不对用户展示。账号名规则：3–20 位小写字母 / 数字 / 下划线，大小写不敏感。

## 3. 流程

### 注册 / 登录

```
客户端                    BFF（youban-companion）               Supabase Auth
  │ POST /api/auth/signup     │                                      │
  │ {account,password,invite} │ 校验账号名 / 密码长度 / 邀请码          │
  │ ─────────────────────────►│ POST /auth/v1/admin/users ──────────►│  service_role，email_confirm=true
  │                           │ POST /auth/v1/token?grant_type=password ►│  anon key
  │ ◄──── {accessToken, refreshToken, expiresAt, user} ───────────────│
```

- 注册走 admin API 是为了**免邮件确认**（服务器没有配 SMTP，也不需要）。
- `accessToken` 是 Supabase 签发的 JWT（HS256，1 小时）。BFF 用同一把 `JWT_SECRET` **本地验签**，不回源。
- `refreshToken` 长期有效、一次一换。客户端在 token 剩余不足 60 秒时自动续期；请求被 401 拒绝时强制续一次并重试。

### 登录后的对账（客户端 `YBAccount.syncProgress`）

1. 先把本机**待发队列**（断网时攒下的进度）发出去。
2. 拉云端进度。
3. 合并：**云端有的以云端为准**；云端没有、本机有的保留并推上去。
4. 把这台设备上游客期间写的攻略簿**认领**到账号（`POST /api/me/claim-device`）。
5. 该账号没有记录的游戏，进度显示为 0。

> 游戏 JSON 里的 `currentPct`（例如黑神话 61%）是**演示用默认值**，只对游客显示。登录用户看到的永远是自己的数据。

### 换账号不串数据

本机记着「这份本机进度属于谁」（`yb_progress_owner`）。用另一个账号登录时，上一个人的本机进度和待发队列**一条都不会**被推到新账号。

### 认领规则

| 情形 | 处理 |
|---|---|
| 账号在该游戏**没有**攻略簿 | 设备簿改挂到账号名下 |
| 账号在该游戏**已有**攻略簿 | 保留账号的；设备簿原样留着，不合并、不覆盖、不删除 |

不合并的理由：两本簿的状态卡可能矛盾（不同流派、不同卡点），自动合并只会产出一本错的。

## 4. 接口契约

基址：`https://<API 域名>/youban-api`。错误统一为 `{ "error": "中文原因", "code": "机器码" }`。

| 方法 | 路径 | 身份 | 请求 | 响应 |
|---|---|---|---|---|
| POST | `/api/auth/signup` | 无 | `{account, password, invite, nickname?}` | 会话 |
| POST | `/api/auth/login` | 无 | `{account, password}` | 会话 |
| POST | `/api/auth/refresh` | 无 | `{refreshToken}` | 会话 |
| GET | `/api/me` | 登录 | | `{id, account}` |
| GET | `/api/me/progress` | 登录 | | `{progress:[{gameId,pct,source,updatedAt}]}` |
| PUT | `/api/me/progress/:gameId` | 登录 | `{pct, source?}` | 写入后的那一行 |
| POST | `/api/me/claim-device` | 登录 + 设备号 | | `{claimed:[gameId], kept:[gameId]}` |
| GET | `/api/content/manifest` | 无 | | `{games:[{id,hash}]}` |
| GET | `/api/content/games/:id` | 无 | | 游戏 JSON 全文，带 `ETag` |
| * | `/api/companion/:gameId…` | 登录**或**设备号 | 见 `backend/bff/README.md` | |

会话对象：`{ accessToken, refreshToken, expiresIn, expiresAt, user: { id, account, nickname, createdAt } }`

| 状态码 | code | 含义 |
|---|---|---|
| 400 | `bad_account` / `bad_password` | 账号名或密码不合规则 |
| 401 | `bad_credentials` | 账号或密码不对 |
| 401 | `unauthorized` / `session_expired` | token 无效或续期失败，客户端应回登录页 |
| 403 | `bad_invite` | 邀请码无效 |
| 409 | `account_taken` | 账号已被注册 |
| 429 | `too_many_attempts` | 同账号 10 分钟内错 5 次 |
| 503 | `auth_not_configured` | 服务端未配账号所需变量 |

**一条重要的行为约定**：请求带了 token 但 token 无效时，服务端回 401，**不会**悄悄降级成设备身份。否则会出现「明明登录了，聊天却记到另一本簿里」。

## 5. 数据表

迁移文件：`backend/supabase/migrations/0001_init.sql`、`0002_companion.sql`。全部表开了行级安全（RLS），策略是「只有本人」。BFF 用 `service_role` 访问并在代码里强制 `user_id` 过滤；RLS 是第二道防线。

| 表 | 主键 | 作用 |
|---|---|---|
| `auth.users` | `id` | 账号（Supabase 管理） |
| `profiles` | `user_id` | 昵称、头像（目前昵称存在 `user_metadata`，此表未启用） |
| `user_game_progress` | `(user_id, game_id)` | 当前进度：`current_pct`、`source`（manual / steam / screenshot） |
| `progress_events` | 自增 | 进度历史，只追加。用于曲线与审计 |
| `user_platform_links` | `(user_id, platform)` | 平台绑定（Steam 已有后端，客户端未接） |
| `companion_sessions` | `id` | 一人一游戏一本簿；`user_id` 与 `device_id` 二选一 |
| `companion_messages` | 自增 | 全量对话 |
| `companion_profiles` | `session_id` | 状态卡（长程记忆） |
| `games` | `id` | 游戏内容分发副本 |

删除账号 = 删 `auth.users` 一行，其余全部 `on delete cascade`。

## 6. 已验证

| 场景 | 方式 | 结果 |
|---|---|---|
| 注册 / 重复注册 / 错邀请码 / 错密码 / 续期 / 无 token / 伪造 token | 服务器上对真实 Auth 服务逐条调用 | 状态码全部符合上表 |
| 进度写入并钳制到 0–100 | 同上，写入 140 | 存为 100 |
| 设备簿认领 | 同上 | 认领后账号可读到 |
| 界面注册 → 拖进度到 42% → 云端读回 | 浏览器实测 | 云端为 42 |
| **换设备**：清空本机数据与设备号后用同账号登录 | 浏览器实测 | 进度 42%、攻略簿历史都回来了 |
| 刷新页面 | 浏览器实测 | 免登录直接进应用 |
| 单元测试 | Vitest | 账号相关 27 个用例，含换账号不串数据、断网入队补发、续期并发只发一次 |

测试账号均已删除。

## 8. 待讨论

| 编号 | 问题 | 我的建议 |
|---|---|---|
| **A1** | 账号名 + 密码只是内测过渡，还是长期保留为一种登录方式 | 长期保留。桌面端用户未必愿意扫码或收短信 |
| **A2** | token 存 `localStorage`。是否改 HttpOnly Cookie | 网页端改 Cookie 更抗 XSS，但 Tauri / Electron / 小程序各有差异。建议：保持现状，同时收紧 CSP（已是 `script-src 'self'`）；桌面端日后改用系统钥匙串 |
| **A3** | 进度冲突策略「后写为准」是否足够 | 足够。若要更稳，可加「云端值比本机新且差距 > 20% 时提示用户选择」 |
| **A4** | 游客的攻略簿存在云端、按设备号归属。设备号丢了就找不回 | 可接受，界面已提示「数据只存在这台设备」。也可改为游客不落库 |
| **A5** | 对话内容是否加密存储 | 库在自己服务器上、只本机可达。建议先做备份与访问审计，应用层加密放到对外收费之前 |
| **A6** | 未成年人 / 实名 | 游伴不是游戏，不涉及防沉迷。但手机号登录即带实名属性，隐私政策须覆盖 |
