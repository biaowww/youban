# 进度识别可行性评估 · 截图 AI vs Steam 成就

> 问题：如何自动判断玩家当前处于流程的哪个点（progressPct）。两条路线：**Steam 成就映射**、**截图 AI 识别（Claude Vision）**。结论先行：**两路都可行且天然互补——成就路线已验证、v1 直接上；截图路线可行但需一轮 PoC 定准确率，作 v1.5 兜底**。UI 的「更新进度」三 Tab（手动/Steam/截图）已为两者预留了位置。

## 路线一：Steam 成就 → 进度（已验证，推荐 v1）

**原理**：每款游戏 JSON 已有 `achievements[]`（steamId → progressPct 映射表）；拉玩家已解锁成就与映射表求交集，`currentPct = 已解锁里 progressPct 的最大值`。

**现状——引擎已经做完**：`src/services/steam/` 纯逻辑引擎 + BFF 契约 + Mock 客户端 + 16 条测试全绿（部分解锁/全解锁/私密档案/无映射全覆盖）。接真只差：BFF 两个端点（持 Key 代调 Steam）+ UI 接线。

| 维度 | 评估 |
|---|---|
| **准确性** | 高且确定性——成就解锁是硬事实，无识别误差 |
| **粒度** | = 剧情成就间距，约每 10–15% 一档（TLOU1 8 档、黑神话 10 档）；档间位置不可知 |
| **成本** | ≈0（Steam Web API 免费，限速内） |
| **覆盖** | 仅 Steam 平台 + 有剧情成就的游戏；**档案必须公开**（私密→引擎已返回可识别降级错误，UI 提示即可） |
| **前置** | BFF 上线（后端 v1 计划内）；**各游戏真实成就 apiname 核对**（当前映射表是合成占位，需逐款对照 SteamDB 换真值——数据工作量约半天/6 款） |
| **风险** | 低。唯一注意：多周目/成就乱序时 max 策略可能偏高，可后续加「按最近解锁时间」备选 |

**结论：可实现性 9/10**，是自动同步的主力路线。

## 路线二：截图 AI 识别（Claude Vision，v1.5 兜底）

**原理**：玩家上传游戏截图 → BFF 转发 Claude Vision → 识别所处章节/场景 → 映射 progressPct。

**关键设计——让模型做选择题而不是开放题**：我们的每款 JSON 已有 `chapters[].name/planet/keyEvent` + `bossSaves[].name`，这是**现成的 grounding 词表**。Prompt 里带上该游戏的候选章节列表，让 Vision 在有限选项里匹配画面文字/场景特征，准确率远高于开放识别。这是我们独有的数据优势。

**输入质量分三档**（决定产品引导）：

| 截图类型 | 可识别度 | 说明 |
|---|---|---|
| A · 章节选择/存档界面 | **高** | 直接含章节名文字，OCR 级任务 |
| B · 任务日志/地图/目标界面 | **高** | 含任务名/地名，与 chapters.planet/playerGoals 可对齐 |
| C · 随机战斗/过场画面 | 低–中 | 只能凭场景美术猜大概区间 |

→ 产品上引导用户截 A/B 类（「打开任务日志截图」），C 类给低置信度提示。

| 维度 | 评估 |
|---|---|
| **准确性** | A/B 类预期高（待 PoC 定量）；必须配**确认 UI**（"识别为《第三回：小西天》，约 43%？"）——识别是建议，用户点确认才写进度 |
| **粒度** | 章节级（与手动选章节相同），部分画面可到 Boss 级 |
| **成本** | Haiku 4.5 单图约 $0.003–0.01，用户低频手动触发，可忽略 |
| **覆盖** | **全平台**（主机/WeGame/手游都行）——这是它存在的意义：补 Steam 覆盖不到的场景（非 Steam 平台、档案私密、无成就游戏） |
| **前置** | BFF `/api/vision/progress` 端点（ANTHROPIC_API_KEY 服务端持有）；小程序端注意图片压缩上传 |
| **风险** | 中：中英文界面差异、mod/画质影响、误判 → 确认 UI + 置信度阈值兜底；模型 API 需梯子/代理的服务器网络问题（offcircle-cloud 已有出站方案） |

**结论：可实现性 7/10**，值得做，但先 PoC。

**PoC 方案（建议 1 天）**：取 3 款游戏（黑神话/TLOU1/杰迪）× 每款 A/B/C 三类截图各 ~8 张（网上截图即可），跑 Haiku 4.5 + 候选章节 prompt，统计 top-1 章节命中率。**A/B 类 ≥80% 即可排产**；顺带产出最优 prompt 模板。

## 双路线协同（最终形态）

```
自动层：Steam 成就（后台静默同步，Steam 用户零操作）
手动层：截图识别（全平台兜底，一张图更新进度）
保底层：手动选章节（现有功能，永远可用）
```

三层写同一个 `user_game_progress`（带 source 字段），UI 已有三 Tab 对应。**排期建议**：v1 = 成就路线接真（BFF 就绪即上）+ apiname 核对；v1.5 = 截图 PoC → 上线。
