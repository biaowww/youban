# 后端 v1 · 架构与数据库设计

> 落地 PRD v0.3「线上数据库 + 账号体系」。方案基调已定：**自托管 Supabase 部署在腾讯云 offcircle-cloud**（国内延迟 50–100ms；小程序要求备案域名，Cloud 域名不可备案）。本文是可执行设计：库表已写成迁移 SQL，seed 脚本已备好。

## 总架构

```
┌────────────────────────┐        ┌─────────────────────────────────────────────┐
│ 客户端                  │        │ offcircle-cloud（腾讯云 Ubuntu）              │
│  Electron / Tauri / PC │ HTTPS  │  nginx ──┬── /rest /auth /storage → Supabase │
│  微信小程序              │ ─────► │          │   (docker compose 自托管)          │
│  （同一套 renderer）     │        │          └── /api → youban-bff (Node,systemd)│
└────────────────────────┘        │                ├ STEAM_API_KEY（服务端 only） │
                                  │                ├ 微信 appid/secret            │
                                  │                └ ANTHROPIC_API_KEY（截图识别） │
                                  └─────────────────────────────────────────────┘
```

- **Supabase 自托管** = Postgres + GoTrue(Auth) + PostgREST(自动 REST API) + Storage。客户端持 **anon key** 直连 REST，安全靠 **RLS**。
- **youban-bff** = 独立小 Node 服务（Fastify/Express，systemd 常驻）。凡是**需要服务端密钥**的都走它：Steam Web API、微信 code2session、Claude Vision。**可直接复用仓库 `src/services/steam/`**（progress.js / client.js 是双环境模块，Node 直接 require；把 `MockSteamClient` 换成真 HTTP 实现即可，契约已定义）。

## 数据库（已写成 `backend/supabase/migrations/0001_init.sql`）

| 表 | 作用 | 访问 |
|---|---|---|
| `games` | 游戏内容库：可查询列 + **`data jsonb` 全量文档**（与 `src/data/games/*.json` 同构，客户端 `adaptGame` 零改造直接吃）；`version` 供缓存失效 | 公共只读（anon 可 select `published`），写只走 service_role |
| `profiles` | 用户资料（1:1 `auth.users`） | RLS 仅本人 |
| `user_platform_links` | 平台绑定：steam(SteamID64) / wechat(openid) / wegame / psn | RLS 仅本人 |
| `user_game_progress` | 当前进度（1 行/用户/游戏）：`current_pct` + `source(manual/steam/screenshot)` + `matched_achievement` | RLS 仅本人 |
| `progress_events` | 进度历史（追加式，曲线/审计） | RLS 仅本人 |

**为什么 jsonb 文档而不拆全关系表**：客户端消费的就是 JSON 文档形状（`adaptGame` 适配），拆表徒增 join 与同步成本；`validate-games.js` 已在 CI 层保证文档质量。需要精细查询（如"按章节搜索"）时再拆，迁移路径保留。

**内容更新流**：改 `src/data/games/*.json`（过 validate/test）→ `node backend/scripts/seed-games.mjs`（哈希比对，内容变了才 upsert 并 version+1）→ 客户端按 `version` 失效缓存。**仓库 JSON 仍是内容创作真相源**，线上库是分发层。

## 账号体系（分两阶段）

**阶段 A（Electron/PC，先行）**：Supabase Auth 内置能力——邮箱 OTP 或**匿名会话**（开 anonymous sign-in，先用后绑定），零自研。
**阶段 B（微信小程序，备案后）**：
1. 小程序 `wx.login()` 拿 `code` → 调 BFF `POST /api/auth/wechat {code}`；
2. BFF 用 appid+secret 调 `code2session` 拿 `openid`（secret 只在服务端）；
3. BFF 按 openid 在 `auth.users` 找/建用户（GoTrue admin API），写 `user_platform_links(wechat, openid)`；
4. 用 Supabase **JWT_SECRET 签一个含 `sub=用户uuid` 的 JWT** 返回小程序 → 之后小程序直连 PostgREST，RLS 生效。

**Steam 绑定**（阶段 A 即可做）：客户端跳 Steam OpenID 2.0 登录页 → 回调 BFF 验证签名拿 SteamID64 → 写 `user_platform_links(steam)` → 之后 `GET /api/steam/progress?gameId=` 由 BFF 持 Key 拉成就、跑 `progressFromAchievements()`、返回 `GameProgress`。

## BFF 端点契约（v1 全集）

| 端点 | 作用 | 密钥 |
|---|---|---|
| `POST /api/auth/wechat` | code2session → 发 Supabase JWT | 微信 secret |
| `GET  /api/auth/steam/login` + `/callback` | OpenID 2.0 绑定 Steam | — |
| `GET  /api/steam/owned` | 拉用户游戏库（对齐 client.js 契约 `getOwnedGames`） | STEAM_API_KEY |
| `GET  /api/steam/progress?gameId=` | 成就→进度（复用 services/steam/progress.js） | STEAM_API_KEY |
| `POST /api/vision/progress` | 截图识别进度（v1.5，见可行性评估文档） | ANTHROPIC_API_KEY |

## 客户端接入（改动极小）

`renderer/adapt.js` 的 `loadRawGames()` 已是多源自适应（Tauri/Electron/`__YB_RAW__`），加一个**线上源**放最前：

```
线上 REST（anon key，带 version 缓存） → 失败回落本地缓存 → 再回落打包 JSON
```

进度写回：`setValue` 后 debounce upsert `user_game_progress` + append `progress_events`；离线队列，重连补写。**离线优先不变**——线上只是同步层，断网照常可用。

## 部署计划（offcircle-cloud）

**第 0 步·前置确认**（拿到 SSH 后我上去查）：服务器**地域**（大陆才能出备案授权码；若是香港则备案需另购大陆机）、规格（Supabase 全家桶建议 ≥2C4G；紧张则精简 profile：db+kong+auth+rest，去 realtime/studio/analytics）、Docker 与磁盘。
1. `git clone supabase/docker` → 配 `.env`（POSTGRES_PASSWORD / JWT_SECRET / ANON_KEY / SERVICE_ROLE_KEY 全新生成）→ `docker compose up -d`；
2. 跑 `0001_init.sql` → `seed-games.mjs` 导入 6 款；
3. `youban-bff` 部署（独立非 root 用户 + systemd，沿用服务器既有隔离策略；注意 `/root/.bashrc` 全局代理不被 docker/systemd 继承，镜像拉取如需代理单独给 docker daemon 配）；
4. nginx：**备案前**不挂域名 80/443（大陆机未备案域名会被阻断）——开发期用 `IP:端口` 或 SSH 隧道访问；**备案后**切 `api.<备案域名>` + certbot TLS。

## 安全边界（硬规矩）

- **进客户端的只有 anon key**（RLS 兜底）；service_role key、STEAM_API_KEY、微信 secret、ANTHROPIC_API_KEY 只存在服务器 env。
- 小程序 request 合法域名只能填备案过的 HTTPS 域名 → **备案是小程序上线的硬前置**（见《小程序域名ICP备案手册》）。
